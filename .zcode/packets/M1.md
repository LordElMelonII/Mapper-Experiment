# PKG A-001 — Model validators & schema migration (C30, C31, F50)

Mission: implement `validateWorldMap` / `validateOverlay` (field-precise, collected
errors) and the versioned migration mechanics, each rule proven by an asserting test.

Read: .zcode/agents/graph-engine.md (your charter). AGENTS.md is injected above and binds you.

Context (verbatim, with IDs):

  C30 — "Reject-before-mutate. Validators run before any graph change; errors are
  field-precise and collected (multiple issues per report, not first-only)."

  C31 — "Versioning. An unknown *newer* schema version is refused with a clear
  message; a known-older one is migrated on load, one migration step per version."

  F50 — "Validation & migration — malformed or future-version data is rejected with
  precise messages, never half-loaded."

  EXECUTION-PLAN §6.2 (Data bullets, yours only): "duplicate ids, dangling edge
  endpoints, NaN coordinates, edges into compound parents ⇒ validator rejects
  pre-`cy.add`; imported map with newer `schemaVersion` ⇒ refuse with toast".

  Types: import from `src/core/api.ts` — the frozen contract. Never edit it.

Deliver (exhaustive — these files, no others):

  1. `src/core/model/validate.ts` — exports:
     - `CURRENT_SCHEMA_VERSION = 2`
     - `interface ValidationIssue { path: string; message: string }`
     - `class MapValidationError extends Error` carrying `issues: ValidationIssue[]`
       (the message summarizes, e.g. "invalid map data: 3 issue(s)"; the array is
       the field-precise report C30 requires)
     - `validateWorldMap(data: unknown): WorldMapData` — collects EVERY issue, throws
       MapValidationError if any; returns the typed map on success; never mutates input
     - `validateOverlay(overlay: unknown, map: WorldMapData): ChatMapOverlay` — same
       contract, validated against an already-valid map
  2. `src/core/model/migrate.ts` — exports:
     - `type MigrationStep = (data: any) => any`
     - `migrateWorldMap(data: unknown, migrations: Record<number, MigrationStep> = {}): WorldMapData`
       — semantics: not an object / missing `schemaVersion` ⇒ refuse; version > CURRENT
       ⇒ refuse with a clear message (C31); version === CURRENT ⇒ `validateWorldMap` and
       return; version < CURRENT ⇒ apply steps v→v+1 in ascending order, then validate;
       a needed step that is not registered ⇒ refuse with a clear message. The default
       table is EMPTY at M1 — there is no real v1 data; the optional `migrations`
       parameter exists so tests (and future real steps) prove the mechanics.
  3. `tests/unit/model/validate.spec.ts` — one asserting test per rule below, citing IDs
  4. `tests/unit/model/migrate.spec.ts` — version-2 passthrough validates; newer version
     refused (C31); older version migrates through a registered synthetic step then
     validates; older version without a registered step refused; missing version
     refused; non-object input refused.

Validation rules for `validateWorldMap` (each needs a test):
  - `schemaVersion` must equal CURRENT_SCHEMA_VERSION (validate sees post-migration data)
  - `id`, `name`: non-empty strings
  - `layers`: array with ≥ 1 entry; each has non-empty `id`/`name`; layer ids unique
  - `scale`: `unitPerPx` finite > 0; `unitLabel` non-empty; `unitKind` ∈ {distance, time};
    `terrainMultipliers` and `speed` values, when present, finite > 0
  - nodes: `id` non-empty and unique across all nodes; `label` non-empty; `kind` ∈ the
    NodeKind union; `layer` references an existing layer id; `parent` (when set)
    references an existing node id, is not the node itself, is on the same layer, and
    parent chains must not cycle; `position` (when set) has finite `x`/`y` (NaN and
    ±Infinity rejected); `aliases` (when set) an array of unique non-empty strings;
    `transit.type` ∈ {train, port, subway}; `origin` ∈ {authored, user}
  - edges: `id` unique; `source`/`target` reference existing node ids and differ
    (no self-loops); source and target are LEAVES — no other node has
    `parent === source|target` (C1, §6.2 "edges into compound parents"); `modes` keys
    ∈ {walk, car, train}; each ModeSpec: `allowed` boolean, `authoredMinutes` (when set)
    finite ≥ 0, `multiplier` (when set) finite > 0; `terrain` in the Terrain union;
    `authoredDistance` (when set) finite ≥ 0; `blocked` (when set) carries a non-empty
    `reason`; `curve.distances` numbers; `fare` finite ≥ 0
  - an edge whose `modes` is `{}` is LEGAL (never traversable; routing returns ∞ per
    C14 row 2) — do not reject it

Validation rules for `validateOverlay` (against the map):
  - `mapId`: string or null; `currentLocationId`: string or null — if it references a
    node that exists, that node must be a leaf (containers never hold the pin, C1/F27);
    if it references nothing, it is NOT an error (C27 orphan policy handles staleness
    at materialization — A-002); `travelMode` ∈ {walk, car, train} and required;
    `statusNote` (when set) a string
  - `userNodes`: full node rules above, plus: ids unique within the overlay AND not
    colliding with library node ids; `parent` is FORBIDDEN on user nodes (§6.2: a tap
    inside a compound yields a top-level user node); `layer` must exist in the map
  - `userEdges`: full edge rules above; endpoints must exist among library ∪ overlay nodes
  - `blocked`: every key must reference an edge in library ∪ `userEdges` (dangling ⇒
    reject); every value a non-empty string

Constraints:
  - `src/core` purity (R5, lint-enforced): hand-rolled validators, imports of types only
    from `../api`; no dependencies, no JSON-schema libraries, no DOM, no console
  - Do NOT touch `src/core/api.ts`, the facade, the effective graph, fixtures, or any
    file outside the four listed — those are A-002/A-003
  - Ponytail: plain functions and interfaces; no class hierarchy, no builder patterns

Acceptance: `npm run verify` green (typecheck + boundary lint + vitest); every rule
above covered by an asserting test citing C30/C31/F50/§6.2 as applicable; at least one

# PKG A-002 — Effective graph + the M1 facade commands (C8, C24, C27, C1, R2)

Mission: implement `buildEffectiveGraph` (library ∪ overlay, atomic, orphan-pin flag)
and wire the seven M1 facade commands over it; every other facade command keeps

Prerequisite: PKG A-001 landed — `src/core/model/validate.ts` and `migrate.ts` exist.

Context (verbatim, with IDs):

  C8 — "Materialization. The effective graph is rebuilt from library + overlay on
  every change (edit save, overlay mutation, map/fork switch). Rebuild is atomic:
  queries never observe a half-applied state."

  C24 — "Live references. A chat's map is the library object itself; edits propagate
  on next materialization, and affected chats are notified ('map updated') (D33)."

  C27 — "Orphan policy. If materialization finds the pin's node deleted: keep the pin,
  mark it invalid, degrade the snapshot to a warning, pause injection until re-pinned.
  Never silently snap to a neighbor (D39)."

  C1 — "Leaf-to-leaf. Arcs terminate on leaf nodes only. Containers (districts,
  cities) organize and label; they never connect and never hold the pin."

  R2 — "Commands only. The frontend mutates nothing directly; every change is a facade
  command." The facade surface is frozen (CORE.md §9): you implement bodies, never

Deliver (exhaustive — these files, no others):

  1. `src/core/model/effective.ts` — exports:
     - `interface EffectiveGraph { mapId: string | null; nodes: MapNodeData[];
       edges: MapEdgeData[]; pin: { id: string | null; valid: boolean } }`
     - `buildEffectiveGraph(map: WorldMapData | null, overlay: ChatMapOverlay): EffectiveGraph`
       — semantics: nodes = map.nodes ∪ overlay.userNodes; edges = map.edges ∪
       overlay.userEdges; for each edge, if `overlay.blocked[edge.id]` exists the edge
       carries `blocked: { reason }` with the overlay's reason (a library-level blocked
       stays blocked regardless — the overlay can only add, never lift); blocked keys
       whose edge no longer exists (possible after a live library edit, C24) are
       dropped silently (C32 degrade); `pin.id = overlay.currentLocationId`;
       `pin.valid` = id set ∧ node exists in the merged node set ∧ node is a leaf
       (no other node parents to it). A single synchronous pass — atomicity is
       structural (C8). `map === null` ⇒ empty nodes/edges, pin invalid.
  2. `src/core/facade.ts` — implement these bodies (interface untouched):

       REFERENCES (C24: the host may mutate the library object in place), never copies

       reject-before-mutate — invalid input leaves prior state untouched), then store
       both references, mark stale
     - `materialize()`: rebuild the effective graph from the stored references (this is
       the C24 hook for host-side in-place library edits); no-op when nothing is loaded
     - `validateImport(data)`: `validateWorldMap(data)` — pure, no state change
     - `migrateData(data)`: `migrateWorldMap(data)` → returns the validated
       WorldMapData; pure, no state change
     - `setCurrentLocation(id | null)`: throws `Error('[TravelMapper] no map loaded')`
       when nothing is loaded; with an id, it must reference a LEAF node of the
       effective graph (containers never hold the pin, C1 — unknown id or container ⇒
       throw a field-precise error); then set `overlay.currentLocationId` and mark
       stale. Moving the pin is silent (D38) — no other side effects.
     - `setStatusNote(note | undefined)`: set/clear `overlay.statusNote` (D17); mark stale
     - `setTravelMode(mode)`: set `overlay.travelMode` (D19); mark stale
     - relabel exactly two stubs from `todo('M1', …)` to `todo('Phase 3 M4', …)`:
       `forkMap`, `saveForkToLibrary` (D56 — forks have no consumer before Phase 3 M4)
     - every command still unimplemented keeps throwing its exact current TODO marker
     - keep a private `ensureFresh()` that rebuilds when `stale` (no callers yet — the
       M2 queries will call it; mutations only set the flag, per C8 rebuild-on-change)
  3. `tests/unit/facade.spec.ts` — update (do not delete): the surface test stays
     verbatim; the every-stub-throws test now asserts TODO throws for exactly the
     still-unimplemented commands (list them explicitly; the seven implemented ones are
     gone from that list)
  4. `tests/unit/facade.m1.spec.ts` — behavior, citing IDs:
     - loadMap with invalid map ⇒ throws collected MapValidationError AND prior loaded
       state survives untouched (C30)
     - loadMap valid ⇒ materialize() yields the merged graph (C8)
     - C24 live reference: mutate the library object in place after load, call
       materialize(), the effective graph reflects the change
     - setCurrentLocation: leaf ok + silent; container ⇒ throw (C1); unknown ⇒ throw;
       null clears; no map loaded ⇒ throw
     - setStatusNote / setTravelMode round-trip (D17/D19)

  5. `tests/unit/model/effective.spec.ts` — builder units (C8 merge, blocked union +
     cannot-lift-library-block, stale-block drop, pin validity incl. leaf check, null map)

Constraints:
