Context (verbatim, with IDs):

  C9 — "Orientation. Origin top-left; x grows East; y grows South (Δy < 0 ⇒
  North). Encoded in exactly one function; unit tests pin the 45° boundaries."

  C10 — "Cardinality. Eight-way directions (N, NE, E, …) computed from Δx and
  Δy. Cross-layer arcs have no geographic direction and are reported without

  C12 — "Authored semantics. An authored distance is the straight-line
  separation between two nodes ('air travel' distance), never a padded road

  C14 — "Cost precedence (per arc, per mode — the normative order):
    1. arc blocked → ∞
    2. mode not allowed on the arc → ∞
    3. authored time → that value (normalized minutes)
    4. authored distance → converted via the mode's speed (when speeds are defined)
    5. geometric distance × scale × terrain multiplier → converted via speed when defined
    6. no speeds defined anywhere → cost is denominated in canonical units;
       routing optimizes by distance and every label says so"

  C15 — "Routing currency. Minutes whenever time is derivable; otherwise
  canonical units. One currency per route computation — costs are never mixed
  within a route."

  FX5 — "Precedence matrix. Every row of C14 exercised by a unit test,
  including blocked, disallowed-mode, authored-time, authored-distance,
  terrain, and no-speeds cases."

  EXECUTION-PLAN §6.2 (Geometry & routing bullets, yours): "cardinal at 45°
  boundaries; zero-distance nodes; … authored-time edges must not accrue
  terrain multipliers".

  The cardinal encoding (EXECUTION-PLAN §3.4, normative — implement verbatim):
    const COMPASS = ['E', 'NE', 'N', 'NW', 'W', 'SW', 'S', 'SE']; // CCW from East, y flipped
    const a = Math.atan2(-dy, dx);       // flip y: north becomes +90°
    const i = Math.round((a < 0 ? a + 2π : a) / (π / 4)) % 8; → COMPASS[i]

  Types: import from `src/core/api.ts` — frozen. ModeSpec.multiplier is
  documented there as "relative factor on derived time" — it applies ONLY to
  time derived via speed conversion (rows 4–5 with speeds), never to authored
  minutes (row 3) and never in no-speeds canonical-unit costs (row 6).

  C14 formula ruling (normative for this packet; the §3.4 edgeCost sketch is
  R0-illustrative and differs — C14's rows win):
    row 1: edge.blocked set ⇒ Infinity
    row 2: no spec for the mode, or spec.allowed === false ⇒ Infinity
    row 3: spec.authoredMinutes != null ⇒ return it (no terrain, no multiplier —
           authored values override absolutely, D14)
    row 4: edge.authoredDistance != null ⇒ units = authoredDistance (C12: the
           TRUE separation — terrain never applies to it; terrain corrects
           geometric estimates only)
    row 5: else units = euclid(positionOf(source), positionOf(target)) ×
           scale.unitPerPx × (scale.terrainMultipliers?.[edge.terrain ?? 'plain'] ?? 1)
    then: if scale.speed?.[mode] is defined ⇒ return units / speed × 60 ×
           (spec.multiplier ?? 1)   [minutes]
          else ⇒ return units        [row 6: canonical units]
  Degenerate rule (pin it): a node without a position contributes a geometric
  term of 0 — an unpositioned endpoint makes the geometric distance 0, not ∞
  (authored values remain the real authoring tool; the editor positions nodes
  on creation, so this is a transient state).
