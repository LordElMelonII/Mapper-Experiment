Normative rulings for this packet (orchestrator):

  - Parsing: `KEY:` maps abbreviations to full names (they become node
    labels); `DIST(min)` rows are walking minutes between walking-network
    nodes; `TRANSIT` rows carry unit-suffixed values with a mode tag —
    `<n>h(mode)` ⇒ authoredMinutes n×60, `<n>km(mode)` ⇒ authoredDistance n;
    modes outside {'walk','car','train'} (e.g. `sub`) are DROPPED with the
    rest of that entry (TravelMode is closed; the drop is pinned by test).
    Malformed rows/keys/numbers ⇒ field-precise error naming the line (C30).
  - Output map: `schemaVersion: 2`, one layer ('Imported'), every node kind
    'location' with a parsed label, `scale: { unitPerPx: 1, unitLabel: 'min',
    unitKind: 'time' }` (D45 time-kind — the coordinates ARE minutes). Every
    DIST pair becomes ONE bidirectional edge (C6) with
    `modes: { walk: { allowed: true, authoredMinutes } }`; TRANSIT entries
    add mode specs to the same pair's edge when one exists, else create the
    edge. Edge ids `import-<from>-<to>` in table order (stable, testable).
    The result must pass `validateWorldMap` (run it inside the importer — a
    map that does not validate is a bug, not caller data).
  - MDS seeding: classical multidimensional scaling over the COMPLETE
    walking submatrix (nodes with a full row/column of walking distances —
    MT has none and is excluded): D² double-centering B = −½ J D² J, top-2
    eigenpairs by power iteration with deflation (tens of nodes, plain
    loops — no library, no Cholesky). Nodes outside the complete submatrix
    (MT): place relative to their strongest constraint — MT at distance
    300 (its train minutes — the only finite value) from the S node, due
    East: `S.position + (300, 0)`; a node with NO finite distance ⇒ position
    omitted (an unpositioned legal node; the degenerate rule prices it 0).
    Deterministic: seed power iteration with a fixed vector (all-ones
    normalized); fix axis-sign ambiguity by flipping so the largest-|x|
    coordinate is positive (golden-stable output).
  - FX3 enforcement (the test): for EVERY walking pair in the table,
    |euclid(a,b) × unitPerPx − tableMinutes| ≤ 0.20 × tableMinutes. If
    specific pairs structurally cannot satisfy this (the table's own
    inconsistencies), STOP AND REPORT the failing pairs with their computed
    deltas — do not relax the bound, do not drop pairs silently (the
    standing instruction; the orchestrator will rule).

Spec (verbatim, with IDs):

  C2 — "Blocked ≠ hidden. A blocked arc is excluded from routing (infinite
  cost) but remains in the snapshot with its reason, so the LLM knows *why*
  a route is unavailable."

  C19 — "Neighborhood. The snapshot's route section lists exactly the arcs
  incident to the pin within its layer, plus cross-layer arcs at the pin.
  There is no same-district sibling awareness (D36)."

  C20 — "Destinations. Shortest paths from the pin to a curated destination
  set (hubs by default), capped (12 entries), with truncation marked."

  C21 — "Text matching. Matching free text to nodes uses word-boundary,
  case-insensitive matching over names ∪ aliases. A failed match produces a
  nearest-suggestions corrective string (D26). The pure matching function
  lives in the core; only its orchestration (subscribing to events, showing
  popups) lives in the host layer."

  C22 — "Snapshot is data; the template is words. The snapshot is a plain
  serializable object. Rendering to the prompt block goes through the user's
  template with a fixed variable contract: `location`, `region`, `layer`,
  `statusNote`, `routes[]`, `destinations[]`, `truncated` (C20's cap dropped
  entries — D63), `unit`, `corrective`. The renderer is core (context
  assembly, C23 exclusion, C32 fallback); the template *content* is user
  data; the template **engine** is an injected Handlebars-shaped capability
  per D62/R5 (host: SillyTavern.libs; tests/harness: devDependency — never
  bundled)."

  C23 — "No machine names. Unnamed user nodes are excluded from every
  prompt-facing structure. `waypoint_3` must never reach an LLM."

  C27 — "Orphan policy. If materialization finds the pin's node deleted:
  keep the pin, mark it invalid, degrade the snapshot to a warning, pause
  injection until re-pinned. Never silently snap to a neighbor (D39)."

  C32 — "Degrade, never throw. Any core failure on a generation-time path
  yields an empty or stale snapshot, not an exception. The host's generation
  must never be endangered by the map."

  FX3 — "Legacy regression. Derived values within ±20% of the original
  lookup table across its pairs — enforced on the metric-satisfiable pairs;
  the 22 pairs the table itself violates are waived under a self-enforcing
  exemption list (D64; the minimal proof: B–H = 15 vs |305−275| = 30 breaks
  the reverse triangle inequality, so no embedding can realize the exact
  table). Enforced at M3 against MDS-importer-seeded maps (D55); the
  hand-authored FX1 fixture is held to plausible geography plus FX2, not to
  FX3. Authored minutes are preserved exactly on every imported edge."

  FX4 — "Template snapshots. Default XML template plus one markdown
  variant, golden-file tested."

  D25 — "Destination awareness. The block includes a compact 'known
  destinations' section (Dijkstra to a curated/hub list, capped) so the LLM
  can answer 'how far is Misaki?' — routed through hub arcs per D16."

  D26 — "Hallucination handling. When a narrated place matches nothing, the
  template carries a corrective line with nearest matches. Matching is
  normalized word-boundary regex over names + aliases, coordinated with
  World Info keywords and respecting that ST users run their own regex
  scripts."

  D55 — "FX3 is the importer's acceptance test (owner-assented, R11). The
  legacy table is not triangle-consistent (e.g. M:O = 20 min vs M→E→O = 52),

  graph. FX3 is enforced at M3 against maps seeded by the MDS lookup-table
  importer; the hand-authored FX1 fixture is held to plausible geography

  D60 — "findRoute mode semantics & route currency (…): (a) Mode selection:
  an explicit `mode` argument is a strict filter (C14 row 2). The default
  (no argument) prefers `overlay.travelMode` on each arc when that mode is
  allowed and prices in the route's currency, and otherwise falls back to
  the cheapest allowed mode in that currency — preference beats price

Register ruling D65 (verbatim, EXECUTION-PLAN R14):

  | D65 | **Snapshot currency integrity & blocked-arc visibility
  (orchestrator, R14; settles the M3 verifier findings 1–2 against
  C2/C15/C17/C19/C22/D60).** The snapshot states ONE currency and every
  cost it presents is stated in it. (a) *Routes currency:* minutes only

  minutes; otherwise canonical units — completeness beats
  minutes-preference (C19's "exactly the arcs incident to the pin"), so a
  live incident arc drops only when it cannot honestly price in the list's
  currency (e.g. a distance-kind map with an authoredMinutes-only arc).
  This supersedes A-008's packet-level "minutes when any arc prices
  minutes; exclude the rest" — the any-rule dropped live arcs (C19) and
  blocked reasons (C2), both proven red by the verifier. (b) *Blocked arcs
  are exempt from currency exclusion — C2 wins over D60's exclusion:* a
  blocked incident arc always lists with its `blockedReason`; the reason,
  not the cost, is the prompt payload. Its cost/mode price best-effort in
  the list's currency; an arc unpriceable there lists with cost 0 and its
  cheapest allowed mode (blocked ⇒ unroutable; the reason carries the
  meaning). (c) *Destinations price in the snapshot's currency:* the hub
  computation runs currency-constrained (no per-run canonical fallback
  inside a minutes snapshot — `computeRoute` gains a forced-currency
  parameter, an internal closure change; the frozen `findRoute` signature

  uniformity is per snapshot, not per leg. FX1 behavior unchanged
  (all-authored minutes); the A-008 mixed-currency FX1 variant test flips
  to the D65 expectation (the stripped arc stays, priced geometrically).
  CORE.md C15/C22 amended in the same change. |
