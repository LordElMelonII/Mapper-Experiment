## Design Specificity Verdict

**Grounded in the product's mechanics, not its soul. Category-interchangeable at the surface layer; genuinely specific in the interaction grammar.** The semantic color contract is real (gold `#ffd166` = party/commit/selection, teal `#4db6ac` = picks/forks, red `#e08a84` = blocked/destructive; canvas node taxonomy location `#4f81b5` / hub `#b0813f` / waypoint `#8064b8`), the copy voice is in-world ("Blocked here", "Tap a node on the map to route there from the pin."), and the route sheet's leg/total structure is the product's one signature composition. Everything else is a dark-mode admin starter: `system-ui` 14px/600 on every control, 8px radii, 1px rgba borders, opaque `#14171c` floaters, no typographic identity (node labels are 12px system-ui), and a mapless first paint that is a blank void with ghost "· ·" separator dots. The engine's honesty is designed; the world is not.

**Deterministic scan** (B): CLI found 1 finding — `broken-image` on `map-viewer.component.html` (a `<img>` with no static `src`) — justified false positive: the element uses Angular `[src]` binding inside an `@if` guard and removes itself on load error. Live overlay found 6 rules across 3 views: `flat-type-hierarchy` (body 14px vs h2 16px, largest adjacent step 1.14:1 vs 1.25:1 target — corroborates A's "no typographic identity"), `low-contrast` (placeholder "Image URL" `#757575` on `#14171c`, 3.9:1 < 4.5:1 — caught by the detector, not A), `dark-glow` (zero-offset glow `#ffba00`), `gpt-thin-border-wide-shadow` (1px border + 24px blur), `cramped-padding` (root children flush against bg), `clipped-overflow-container` (stage and open layer-manager clip positioned children). Agreement: detector and review converge on flat hierarchy and craft-level contrast; A alone caught the structural issues (occlusion, phone boot zoom, form wall); B alone caught the numeric contrast failure.

## Overall Impression

An engineering-honest tool with one designed moment (the gold route total on the phone sheet) wrapped in an admin-panel costume it didn't author. The single biggest opportunity: give the map a world — a typographic and material identity that makes first paint feel like opening an atlas, not a database — while keeping the verified semantic color contract and touch ergonomics.

## What's Working

1. **A real semantic color contract, enforced** — gold/teal/red/amber meanings verified consistent across canvas stylesheet, panels, and rail chrome.
2. **Touch ergonomics that are engineered, not claimed** — every interactive rect ≥44px both orientations; phone sheet stack capped at 70% of stage; avoid-the-selection floater anchoring, measured live.
3. **Honest state language as a design material** — disabled-with-reason, inline confirms with engine-computed casualty counts, field-precise refusal blocks; the UI never lies about what it refused.

## Priority Issues

1. **[P0] The route answer is occluded exactly when it's asked for (desktop, editor mode).** The maximized property panel and route floater share an anchor; property paints on top (property rect(164,112,288,676) fully covers route rect(164,420,288,368)) while the Route toggle glows active. Fix: stagger anchors (route bottom-left, property bottom-right) or collapse route to its drag-header when property opens; the Route toggle must never read active for a covered panel.
2. **[P0] Phone first paint is an illegible dot field.** FX1 boots at zoom 0.282 on 390×844; all 15 labels cull below the zoom floor — the world renders as anonymous specks. Fix: boot phone to a pin-centered, label-legible zoom (fit the pin's neighborhood or clamp with a label-survival floor); "Fit" stays the explicit full-world ask.
3. **[P1] Degraded states render ghost punctuation instead of guidance.** Mapless header shows "· ·"; fresh map shows "· units"; pinless route target renders "→ New place" (empty origin, dangling arrow). Fix: collapse empty header fields; the route panel should say what's missing ("Set where the party is to route from here").
4. **[P1] The property panel is a 9-group wall with the danger zone below the fold.** 838–888px of form in a 676px window; placing a node opens it pre-emptively for a node auto-named "New place". Fix: name-first pattern — focus Name on open, collapse advanced groups (Parent/Layer/Opens layer/Aliases/Block) behind toggles, pin Detach/Delete to a constant footer band.
5. **[P2] The one unthemed control and the one casing split.** The Dim slider is a native UA control (white pill, Arial, in a pitch-dark rail, both breakpoints); mode chips render "Walk/Car/Train" (CSS capitalize) while legs say "walk". Fix: `color-scheme: dark` + `accent-color` on the slider; unify mode casing at the data/display layer.

**Jordan (first-time SillyTavern user):** after Create, nothing instructs that edit-mode canvas taps place places; every node is "New place" ×N with no rename nudge; cannot finish the core loop — no UI sets the party's home (the known owner gap: `setCurrentLocation` has no app-layer caller), so the route line reads "→ New place" with no origin; jargon without glossary ("Fork", "Dim", "Opens layer").
**Casey (phone-only roleplayer, one thumb):** first-paint illegibility (pinch before anything means anything); chrome stacking leaves ~36% visible canvas with the property sheet open in connect mode while copy asks to "tap places on the map"; Delete sits one thumb-slip under Open in every maps row (5 wrapped buttons). Reading routes one-handed is genuinely good; authoring fights the thumb.

## Minor Observations

- Route legs wrap mid-cost on phone-width floaters; consider nowrap + ellipsis or a two-column leg row.
- Property header actions wrap awkwardly at 262px ("Restore" alone on row 2).
- Floater chrome inconsistent: layer-manager gets drag+maximize; maps floater gets neither; two different collapse idioms ("Hide/Show" vs "Route ▾") in the same stack.
- Phone corner state: route sheet expanded + Maps sheet open — route section overflows its host and paints into the Maps sheet band.
- Layer-manager rows are 6 lines each; the background sub-form belongs behind an expander.
- Harness leaks fixture-speak ("Fuyuki & Misaki (FX1)") into the picker — police before ship.
- `input[type=file]` styled like a text input; doesn't signal it opens a file dialog.
- Three pills can stack along the top edge in edit mode with unsaved changes (header grows 36→70px).

## Questions to Consider

1. If the party pin is the story's protagonist, why is setting it the one thing the UI cannot do — and why does the route panel answer that gap with a dangling arrow instead of a sentence?
2. Gold currently means: active toggle, selected node, the pin, primary commit, breadcrumb wayfinding, and the route total. When everything important is gold, what should the user look at first?
3. Desktop is the phone layout with bigger numbers. Is parity really "same chrome," or should the pointer world get its own ergonomics — hover affordances, keyboard, a toolbelt strip?
4. The empty states are honest but sterile. Would one authored moment at mapless boot cost less than the users it saves?
5. Would "Fork", "Dim", "Opens layer", and "Detach from arcs" survive a hallway test with two roleplayers who have never seen this extension?
